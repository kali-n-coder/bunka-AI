# 来校者による待ち時間・混雑情報入力案

クラス企画が忙しく、各企画担当が待ち時間を入力する運用が難しい場合の代替案です。  
来校者に匿名で協力してもらい、待ち時間ではなく **「混雑の目安」** を集める方式を中心に考えます。

## 1. 結論

おすすめは、来校者に正確な分数を入力してもらうのではなく、次のような **ワンタップ式の混雑報告** にすることです。

```text
この企画はいまどれくらい混んでいますか？

[すぐ入れそう] [少し待つ] [かなり混んでいる] [受付停止・満員っぽい]
```

理由:

- 来校者が正確な待ち時間を測るのは難しい。
- 分数入力は面倒で、入力ミスやいたずらが起きやすい。
- 忙しい企画担当に頼らなくても、ざっくりした混雑傾向は集められる。
- 表示も「5分」ではなく「空いていそう」「混んでいそう」にすれば、多少の誤差を許容できます。

## 2. 表示方針

来校者入力をそのまま断定表示しない方が安全です。

避けたい表示:

```text
待ち時間: 10分
```

おすすめ表示:

```text
来校者報告: 少し待つかも
最終報告: 5分前
信頼度: 中
```

または:

```text
混雑目安: 混み気味
最近の報告: 8件
最終更新: 5分前
```

## 3. 入力画面の案

### 3.1 QRコードから入力

各企画の前、またはパンフ・掲示にQRコードを置きます。  
来校者がスマホで読み取ると、その企画の混雑報告画面に飛びます。

画面イメージ:

```text
白龍AIガイド 混雑報告

企画名: オカダナルド
場所: 屋外 3-F

いまの様子を教えてください

[すぐ入れそう]
[少し待つ]
[かなり混んでいる]
[受付停止・満員っぽい]

送信

※正確でなくても大丈夫です。近くで見た範囲で教えてください。
```

### 3.2 企画一覧から入力

待ち時間一覧ページに「混雑を報告」ボタンを付けます。

```text
オカダナルド
混雑目安: 混み気味
[混雑を報告]
```

QRを企画ごとに作る余裕がない場合は、この方式が楽です。

## 4. 入力項目

入力項目は少なくします。

必須:

- 企画名
- 混雑状態
- 送信時刻

任意:

- ひとことメモ

ただし、ひとことメモは荒れやすいので、最初は入れない方が安全です。

おすすめの混雑状態:

| 内部値 | 表示 | 意味 |
| :--- | :--- | :--- |
| `empty` | すぐ入れそう | ほぼ並んでいない |
| `short` | 少し待つ | 少し列がある |
| `busy` | かなり混んでいる | 明確に列がある |
| `closed` | 受付停止・満員っぽい | 入れない、またはかなり厳しそう |

## 5. 分数に変換する場合

画面上でどうしても分数表示したい場合は、来校者入力を直接分数にせず、目安として変換します。

| 報告 | 表示する目安 |
| :--- | :--- |
| すぐ入れそう | 0〜5分 |
| 少し待つ | 10〜15分 |
| かなり混んでいる | 20〜40分 |
| 受付停止・満員っぽい | 受付停止・満員の可能性 |

ただし、来校者入力だけで「確定待ち時間」として表示するのは避けます。

## 6. 集計方法

### 6.1 直近の報告だけ使う

古い報告はすぐ役に立たなくなります。

おすすめ:

- 直近15分以内の報告を使う。
- 15分を超えたら「情報が古い」と表示する。
- 30分を超えたら混雑表示から外す。

表示例:

```text
混雑目安: 少し待つかも
最近の報告: 6件
最終報告: 4分前
```

```text
混雑目安: 情報が古いです
最終報告: 32分前
```

### 6.2 多数決ではなく中央値寄りにする

いたずらで1件だけ「満員」と入っても、表示が壊れないようにします。

例:

- 直近15分の報告を集める。
- `empty=0`, `short=1`, `busy=2`, `closed=3` と数値化する。
- 中央値、または多数派を表示する。
- 報告が2件未満なら「参考情報」と表示する。

### 6.3 信頼度を出す

報告数によって信頼度を変えます。

| 直近報告数 | 表示 |
| :--- | :--- |
| 0件 | 情報なし |
| 1〜2件 | 信頼度: 低 |
| 3〜5件 | 信頼度: 中 |
| 6件以上 | 信頼度: 高 |

## 7. いたずら対策

完全に防ぐのは難しいですが、かなり抑えることはできます。

### 7.1 連投制限

同じ端末から短時間に何度も送れないようにします。

例:

- 同じ端末は1企画につき3分に1回まで。
- 全体でも1分に3回まで。

### 7.2 自由記述を置かない

最初はコメント欄なしが安全です。  
自由記述があると、悪ふざけや個人情報が入る可能性があります。

### 7.3 断定表示しない

来校者報告は必ず「目安」として表示します。

```text
来校者からの報告をもとにした目安です。
実際の状況は現地で確認してください。
```

### 7.4 異常値を無視する

短時間に同じ企画へ大量報告が来た場合は、最新1件だけ使う、またはその端末の報告を一時的に無視します。

## 8. プライバシー方針

来校者の善意入力にするなら、個人情報は集めない方がよいです。

集めないもの:

- 名前
- 学年
- クラス
- 電話番号
- メールアドレス
- 位置情報
- 自由記述コメント

最低限保存するもの:

- 企画ID
- 混雑状態
- 送信時刻
- 連投防止用の匿名ID

匿名IDは、個人を特定するためではなく、連投防止のためだけに使います。

## 9. 来校者への文言

### 入力画面に出す文

```text
近くで見た範囲で、いまの混み具合を教えてください。
正確でなくても大丈夫です。みんなの案内の参考になります。
```

### 送信後の文

```text
ありがとうございます。
あなたの報告は、混雑目安として反映されます。
```

### 一覧画面に出す注意文

```text
混雑目安は来校者からの匿名報告をもとにしています。
実際の待ち時間や受付状況は、現地の案内を確認してください。
```

## 10. 実装案

### 案A: 既存の待ち時間を置き換えず「混雑目安」を追加する

一番安全です。

現在:

```text
待ち時間: 0分
```

変更後:

```text
混雑目安: 少し待つかも
来校者報告: 6件
最終報告: 4分前
```

スタッフ入力がある企画だけ、従来の待ち時間も表示します。

```text
スタッフ更新: 10分
来校者報告: 少し待つかも
```

### 案B: 来校者報告から自動で待ち時間目安を出す

少し便利ですが、誤差が出やすいです。

```text
待ち時間目安: 10〜15分
来校者報告: 5件
```

必ず「目安」と書きます。

### 案C: 企画ごとにQRコードを作る

精度は上がりますが、準備が少し大変です。

メリット:

- その企画の前にいる人が入力しやすい。
- 企画選択ミスが減る。

デメリット:

- 企画ごとのQR掲示物が必要。
- QRを貼る場所の管理が必要。

### 案D: 待ち時間ページからまとめて報告する

準備が楽です。

メリット:

- QRは1つでよい。
- ページ内で企画を選んで報告できる。

デメリット:

- 企画選択ミスが起きる。
- 現地にいない人でも入力できる。

## 11. おすすめ構成

現実的には次がおすすめです。

1. スタッフ入力は残す。
2. ただし、スタッフ入力は無理な企画では使わない。
3. 来校者の匿名報告で「混雑目安」を集める。
4. 表示は分数ではなく、状態表示にする。
5. 直近15分の報告だけ使う。
6. 報告数と最終報告時刻を一緒に出す。
7. 信頼度を出す。
8. 自由記述は入れない。

表示例:

```text
オカダナルド
混雑目安: かなり混んでいる
最近の報告: 8件
最終報告: 3分前
信頼度: 高
```

```text
ともっちゃ
混雑目安: 情報が少ないです
最近の報告: 1件
最終報告: 12分前
信頼度: 低
```

## 12. 当日運用

### 掲示するもの

- 待ち時間ページのQRコード
- 「混雑報告にご協力ください」の一言
- 「目安です。最終案内は現地スタッフへ」の注意

### スタッフが見るもの

admin画面に、来校者報告の一覧を出すと便利です。

表示例:

```text
企画名 | 混雑目安 | 直近報告数 | 最終報告 | 信頼度
```

異常に報告が多い企画や、急に満員報告が増えた企画を見られるようにします。

## 13. 注意点

- 来校者報告は正確な待ち時間ではありません。
- いたずらや勘違いが混ざる前提で設計します。
- 表示は「目安」にします。
- 個人情報は集めません。
- 緊急時や受付停止などは、最終的にスタッフ案内を優先します。

## 14. 実装するなら最初にやること

最初の実装範囲は小さくてよいです。

1. 企画一覧に「混雑を報告」ボタンを追加する。
2. 4択ボタンで混雑状態を送信できるようにする。
3. バックエンドに匿名報告APIを追加する。
4. 直近15分の報告を集計する。
5. 待ち時間一覧に「混雑目安」「報告数」「最終報告」を表示する。
6. admin画面で報告状況を確認できるようにする。

この形なら、スタッフ入力ができない企画でも、来校者の善意で「今どこが混んでいそうか」をある程度見せられます。
