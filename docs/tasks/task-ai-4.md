# タスク細分化：4. UI/UX開発 (task-ai-4.md)

このドキュメントは `task-ai.md` の「4. UI/UX開発」を詳細に分解したものです。

現状では、バックエンドにAIチャット、RAG、展示情報、待ち時間、行程プランナー、スタッフ認証のAPI入口が用意されています。一方で、フロントエンドはまだ Vite 初期画面に近い状態です。ここでは、来場者が実際に使う画面と、スタッフが待ち時間を更新する画面の基礎を作ります。

## 4.1 共通デザインシステム（CSS）の実装
- [ ] Vite 初期画面のCSSを削除または置き換える
- [ ] 白龍AIガイド用の色・余白・文字サイズ・ボタン・入力欄の基本スタイルを定義
- [ ] モバイルとPCの両方で使いやすいレイアウトにする
- [ ] 上部ナビゲーションまたはタブを用意
    - チャット
    - 待ち時間
    - 行程
    - スタッフ
- [ ] 読み込み中・エラー・空データの表示スタイルを用意
- [ ] 画面全体を文化祭の運用ツールとして見やすい密度に整える

## 4.2 モバイル対応のチャット画面コンポーネント作成
- [ ] ユーザー入力欄を作成
- [ ] 送信ボタンを作成
- [ ] 会話履歴の表示を作成
- [ ] AI回答の表示を作成
- [ ] 送信中状態を表示
- [ ] API未起動・Ollama未起動時のエラー表示を整える
- [ ] サンプル質問ボタンを用意
    - 「白龍の舞について教えて」
    - 「空いている展示は？」
    - 「おすすめの回り方は？」
- [ ] ストリーミング表示は後続改善として、まず通常チャットAPIで動かす

## 4.3 待ち時間リアルタイム表示コンポーネントの作成
- [ ] `GET /api/v1/wait-times` を呼び出す
- [ ] 展示名、カテゴリ、待ち時間、更新日時を表示
- [ ] 待ち時間の長さに応じて状態表示を変える
    - 空いている
    - やや混雑
    - 混雑
    - 満員に近い
- [ ] データがない場合はサンプル表示を出す
- [ ] 更新ボタンを用意
- [ ] 後でポーリングやWebSocketに差し替えられる構造にする

## 4.4 行程プランナーのUI（タイムライン表示）の作成
- [ ] 展示IDを入力または選択できる簡易フォームを作成
- [ ] 利用可能時間を入力できるようにする
- [ ] `POST /api/v1/itinerary/plan` を呼び出す
- [ ] 結果をタイムライン形式で表示
    - 訪問順
    - 待ち時間
    - 見学時間
    - 移動時間
    - 経過時間
- [ ] 行程が作れない場合のメッセージを整える
- [ ] 将来的に展示一覧からチェック選択できるようにする

## 4.5 スタッフ用更新ダッシュボード画面の作成
- [ ] スタッフPIN入力欄を作成
- [ ] 展示ID入力欄を作成
- [ ] 待ち時間入力欄を作成
- [ ] `POST /api/v1/exhibitions/{id}/wait-time` を呼び出す
- [ ] 更新成功・失敗メッセージを表示
- [ ] PINは画面内stateに保持し、永続保存しない
- [ ] 誤入力を防ぐ
    - 負の数値禁止
    - 空欄禁止
    - 極端な値の確認

## 4.6 APIクライアント整理
- [ ] `frontend/src/api/client.ts` に展示・待ち時間・行程・スタッフ更新用関数を追加
- [ ] レスポンス型を最低限定義
- [ ] エラー時に画面へ表示しやすいメッセージを返す
- [ ] モック表示と実API表示が混ざっても破綻しないようにする

## 4.7 確認・レポート
- [ ] TypeScriptチェックを実行
- [ ] 画面がビルドできることを確認
- [ ] 実装内容を `docs/reports/report-ai-4.md` にまとめる
- [ ] 現段階でブラウザから何が見えるかを説明する
