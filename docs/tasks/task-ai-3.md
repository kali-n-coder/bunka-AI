# タスク細分化：3. 機能の実装 (task-ai-3.md)

このドキュメントは `task-ai.md` の「3. 機能の実装」を詳細に分解したものです。

現状では、`Exhibition` と `WaitTime` のDBモデルは作成済みですが、展示情報や待ち時間を操作するAPI、展示間の移動距離計算、行程最適化、スタッフ認証はまだ未実装です。RAG & AIロジックと連携できるように、まずはバックエンドAPIとロジックを小さく動かせる形で実装します。

## 3.1 展示情報APIの実装
- [ ] 展示情報用の Pydantic スキーマを作成
    - `ExhibitionCreate`
    - `ExhibitionUpdate`
    - `ExhibitionResponse`
- [ ] `backend/app/api/exhibitions.py` を作成
- [ ] 展示一覧取得APIを実装
    - `GET /api/v1/exhibitions`
- [ ] 展示詳細取得APIを実装
    - `GET /api/v1/exhibitions/{exhibition_id}`
- [ ] 展示作成APIを実装
    - `POST /api/v1/exhibitions`
- [ ] 展示更新APIを実装
    - `PATCH /api/v1/exhibitions/{exhibition_id}`
- [ ] 展示削除APIを実装するか検討
    - 運用中の誤削除を避けるため、最初は無効でもよい
- [ ] カテゴリ別・キーワード検索に対応
- [ ] RAG用データとの関係を整理
    - DBは一覧、位置、カテゴリ、待ち時間表示に利用
    - `docs/data/` はAI回答用の詳細資料に利用

## 3.2 展示待ち時間の更新・取得API
- [ ] 待ち時間用の Pydantic スキーマを作成
    - `WaitTimeCreate`
    - `WaitTimeUpdate`
    - `WaitTimeResponse`
- [ ] `backend/app/api/wait_times.py` を作成
- [ ] 全展示の待ち時間一覧APIを実装
    - `GET /api/v1/wait-times`
- [ ] 特定展示の待ち時間取得APIを実装
    - `GET /api/v1/exhibitions/{exhibition_id}/wait-time`
- [ ] 特定展示の待ち時間更新APIを実装
    - `POST /api/v1/exhibitions/{exhibition_id}/wait-time`
- [ ] 待ち時間の入力形式を決める

    - 「空いている」「混雑」「満員」などの状態
    - 数値と状態の併用
- [ ] `updated_at` を使って、情報の新しさを表示できるようにする
- [ ] 存在しない展示IDへの更新時のエラーハンドリングを実装
- [ ] フロントエンドが扱いやすいレスポンス形式に整える
    - 展示名
    - カテゴリ
    - 現在の待ち時間
    - 更新日時
